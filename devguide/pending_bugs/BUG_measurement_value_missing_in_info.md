# BUG: Measurement value (distance/angle) is missing in `view.measurements.info()`

## Description
When a measurement is created (either interactively or via API), the numerical value of the distance (in Å) or angle (in degrees) is displayed in the viewer's canvas but is not stored in Python's internal state. Consequently, calling `view.measurements.info()` returns metadata about the atoms involved, but lacks the most important piece of information: the result of the measurement.

## Steps to Reproduce
1. Load a system.
2. Create a distance measurement interactively or via `view.measurements.add_distance()`.
3. Check the output of `view.measurements.info()`.
4. **Observed Result:** The dictionary contains `kind`, `tag`, `picks_atom_indices`, etc., but no `value` field.

## Technical Analysis
In `molsysviewer/measurements.py`, the `info()` method iterates over `self._view._measurement_history`. This history stores dictionaries generated by `_build_measurement_message`. Currently, these dictionaries do not include a placeholder or a slot for the numerical result calculated by the frontend.

## Proposed Solution
1. Update the frontend (`viewer.js`) to include the calculated `value` in the `interaction_measurement_created` event payload.
2. Update `_record_measurement` in Python to store this value in the options dictionary.
3. Update `info()` to extract and return the `value` field.
