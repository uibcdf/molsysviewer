# Trajectory transport baseline — July 2026

## Decision

The current JSON transport has a measurable cost for an 18 MB structure
sequence, but
it is not the dominant cost of the end-to-end load. Binary transport and
array-native extraction are accepted pre-1.0 work. Bounded or lazy structure
retrieval remains post-1.0. The optimization starts at Python list
materialization rather than replacing the wire format in isolation.

This benchmark closes Phase 0 of
[`data_plane_architecture.md`](../data_plane_architecture.md).

## Commands

Python preparation, with every case isolated in a fresh process:

```bash
python devtools/benchmarks/trajectory_transport_baseline.py run
```

Chrome/Mol* path for the complete pentalanine structure sequence:

```bash
cd molsysviewer/js
npm run bench:trajectory-transport
```

To reuse a payload already generated by the Python worker:

```bash
MOLSYSVIEWER_TRAJECTORY_PAYLOAD=/tmp/pentalanine-5000.json \
MOLSYSVIEWER_TRAJECTORY_PERF_CASE=pentalanine-5000 \
node tests/perf/trajectory-transport.perf.js
```

## Python preparation

Times are cold-process measurements in milliseconds. `peak RSS growth` is
relative to the process after importing the benchmark dependencies.

| Fixture | Atoms | Structures | JSON size | Convert | ViewerJSON | Normalize lists | JSON encode | Peak RSS growth |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| dialanine | 22 | 1 | 3.4 KB | 3512 | 1.8 | 0.7 | 0.1 | 349 MB |
| pentalanine | 62 | 100 | 0.37 MB | 3524 | 19 | 27 | 13 | 354 MB |
| pentalanine | 62 | 1,000 | 3.68 MB | 3537 | 408 | 289 | 143 | 394 MB |
| pentalanine | 62 | 5,000 | 18.37 MB | 3547 | 1614 | 2124 | 687 | 562 MB |
| chicken villin HP35 | 4,369 | 1 | 0.58 MB | 3523 | 59 | 48 | 14 | 360 MB |

The full pentalanine path spends about 7.97 seconds before delivery. The fixed
~3.5 second conversion cost dominates small cases; ViewerJSON extraction and
conversion to nested Python lists then grow with `atoms × structures`.

The 18.37 MB wire payload corresponds to roughly 562 MB of peak Python RSS
growth. That ratio includes the loaded MolSysMT object, ViewerJSON, nested
lists, and encoded JSON existing during the same operation; it is not a claim
about the wire format alone.

## Chrome and Mol*

The full 62-atom, 5,000-structure pentalanine payload produced:

| Stage | Time |
|---|---:|
| local HTTP fetch as text | 194 ms |
| browser `JSON.parse` | 191 ms |
| Mol* trajectory construction | 183 ms |
| structure change (Mol* frame), median of 10 | 8.3 ms |
| structure change (Mol* frame), maximum of 10 | 13.3 ms |

V8 heap was 74.2 MB before fetch, reached a sampled 106.1 MB during Mol*
construction, and settled at 95.6 MB after load. These are JavaScript heap
figures only. They exclude native Mol* allocations, WebGL resources, GPU
memory, and process overhead, so they are a lower bound rather than a browser
memory budget.

The local HTTP fetch approximates the standalone Qt payload-reference path. It
does not measure AnyWidget comm cloning or the custom Qt URL scheme itself.

## Interpretation

1. JSON transfer plus parsing is material in isolation: approximately 385 ms
   for 18.37 MB.
2. It is still a small part of this cold end-to-end load. Python preparation is
   over an order of magnitude slower.
3. Once loaded, this small topology can change structures within a 16 ms render
   budget. That does not predict performance for a large topology or expensive
   representations.
4. Retaining every structure scales linearly and remains an architectural ceiling.
   The current fixture does not by itself justify implementing a bounded cache
   before 1.0.
5. The pre-1.0 binary proof must compare against the measured fetch and parse
   stages, while a separate upstream study reduces extraction and nested-list
   duplication.

## Follow-up gates

Before making release-level claims for the binary data plane:

- repeat with a released, clean MolSysMT build;
- add at least one representative large-topology structure sequence, not only
  62 atoms across many structures;
- measure AnyWidget comm and the Qt custom-scheme path independently;
- obtain browser process/native and GPU memory, not only V8 heap;
- preserve the current JSON fallback, state v2, replay, and export contracts.
