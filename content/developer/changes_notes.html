  • 2026-07-17: MolSysViewer no longer vendors its own molecular demo systems. demo[...] and the public molsysviewer.systems catalog now resolve every system through MolSysMT’s registry (molsysmt.systems), the ecosystem’s single source of truth, so the demos never drift out of sync with MolSysMT. The five bundled .h5msm files, the molsysviewer/data/ tree, and its packaging entry were removed. Crystal demos (181L, 1TCD) are resolved from the .bcif.gz form so their per-atom b_factor/occupancy are preserved and the chains match what msm.convert('1TCD')/msm.convert('181L') return — the previously bundled .h5msm copies had silently dropped b-factors (even MolSysMT’s own 1tcd.h5msm lacks them), and the .pdb form, while it keeps b-factors, collapses the crystal chains (all waters land on the protein chain). If a demo needs a system MolSysMT does not provide, it is requested from the MolSysMT team rather than vendored.

  • 2026-07-17: Region.set_color_by_attribute() / Whole.set_color_by_attribute() now distinguish a recognized attribute that carries no values in the loaded system (“has no values in the loaded system”) from an unrecognized one, instead of a single misleading “not available” message.

  • 2026-07-17: Per-atom colors (set_color_by_attribute / set_color_by_values) now actually render. The msv-per-atom color theme had two defects that made scalar coloring silently invisible: (1) it only handled StructureElement.Location, so every Bond.Location fell back to the base theme — which meant per-atom colors never showed on bond-drawing representations (ball-and-stick, licorice, line), while cartoon worked; and (2) it resolved the atom via OrderedSet.getAt(unit.elements, location.element), treating a model-level ElementIndex as a position into the unit’s element array, so lookups only succeeded on the first unit and silently missed on every other chain. Both now follow the same convention as the sibling physicochemical theme. Three new JS tests cover the theme’s color() function (previously only the color map was tested, which is why the defects went unnoticed); each half of the fix is mutation-verified.

  • 2026-07-20: Python↔JS boundary audited systematically (devguide/audits/python_js_boundary_audit_2026_07.md), after the same defect shape appeared four times during dogfooding: a public argument accepted and validated by Python that something downstream then ignores in silence. Three scripted sweeps: arguments declared under @digest() with no digester (26 found, each emitting DigestNotDigestedWarning on every call), ops emitted by Python that no frontend handler reads (1 real orphan, dynamic_region_evaluation_warning, out of 89 — the other five candidates were false positives from handler forms the naive sweep missed), and values Python accepts that the frontend does not know (no outstanding mismatch; this is the sweep that would have caught ping-pong vs palindrome). Sweeps 1 and 2 are cheap and deterministic and would have caught every instance found by hand.

  • 2026-07-20: Digesters added for six public arguments that had none: region (focus_region), fade (focus_with_fade), meta (layers.add), layer (regions.set_layer), target (measurements.set_representative_atom) and transaction_id (partial_coordinates_update). Each contract follows its call site: a region or layer accepts a tag or the object itself, fade is a transparency in [0, 1], meta is copied so later mutation of the caller’s dict cannot alter stored state, target is normalized for lookup while the callee still validates it against its own registry, and transaction_id passes through unchanged since the frontend echoes it back. Booleans are rejected where they would masquerade as numbers. Re-running the audit now reports 20 missing arguments instead of 26, all in shapes.

  • 2026-07-20: MolSysView.play() works again. Every one of its arguments defaults to None, but the mode and step digesters rejected None outright, and mode/direction only recognised the molsysviewer.player.* callers while MolSysView.play() normalises to molsysviewer.viewer.play — so v.play() raised ArgumentError, and even an explicit v.play(mode="loop") was refused. Worse, direction="forward" fell through to the 3D-vector branch and was normalised as a spatial direction. Playback was only reachable through v.player.play(mode="loop"). Two latent defects were fixed alongside: direction crashed when caller was None, and step accepted True as a valid integer.

  • 2026-07-20: Trajectory playback modes are actually implemented. playTrajectory accepted a mode and never read it: playback always advanced through Mol*’s wrap-around, so loop worked by accident, once never stopped at the end, and ping-pong never bounced. On top of that the vocabularies disagreed — Python’s public API says ping-pong, the frontend has always called it palindrome — so the mode was dropped even when supplied. The per-tick decision now lives in a pure nextPlaybackStep helper: loop wraps, once clamps to the end frame and stops, and palindrome reverses direction at either end (honouring the step size). ping-pong is accepted as a synonym of palindrome.

  • 2026-07-20: view.trajectory_plot.show() accepts NumPy arrays. Series were validated with isinstance(value, collections.abc.Sequence), which a numpy.ndarray is not, so per-frame data (RMSD, radius of gyration, an energy term, coordinates straight out of MolSysMT) was rejected and users had to call .tolist() by hand. One-dimensional arrays are read as a single series, two-dimensional ones as several, and mappings of arrays work as well.

  • 2026-07-17: Right-dragging the structure no longer leaves the canvas context menu open. The browser fires contextmenu on button press, so the menu appears before a click can be told apart from a drag — and Mol* uses the right button to pan, leaving the menu open for the whole gesture. The menu is now dismissed as soon as the pointer travels more than 5 px (measured radially) from where it opened, so a plain right-click, including a shaky one, still works.

  • 2026-07-17: The structural color selector offers group_name (“Group Name”) instead of residue_name. The panel builds its options from the backend’s scheme list, so this follows from the canonical tag rename; the composer’s fallback list was aligned too. Note that molsysviewer/loaders/load_molsysmt.py deliberately keeps translating group_* to residue_* in the wire payload, because those fields are written into mmCIF atom_site columns (label_comp_id, label_seq_id) where comp/residue is the standard name — that boundary is intentional and stays.

  • 2026-07-17: A pure color change no longer rebuilds the global representation. set_color_scheme() emits the same set_whole_representation op as set_representation(), so the frontend used to destroy and recreate the representations for a mere recolor. That triggered Mol*-internal camera adjustments and made atoms the representation cannot draw (waters under a cartoon) blink out on an operation that should only change color. When the representation, preset and non-color params are unchanged, the color theme is now updated in place; an active per-atom color overlay is preserved and only its base theme is replaced.

  • 2026-07-17: The camera is only preserved across a representation rebuild when a deliberate viewpoint exists. Restoring it unconditionally was wrong: when operations arrive before Mol* has framed a freshly loaded structure — configuring a view before displaying it, or simply running notebook cells faster than the render — the snapshot predates that framing and writing it back overwrote it, leaving the structure rendered but out of sight until the user pressed “Reset view”. A viewpoint counts as deliberate when the user has orbited/zoomed/panned, when a camera snapshot was applied explicitly, or when the view was focused on a selection; otherwise Mol* is left free to frame the structure. Diagnosed by disabling the restore entirely, which fixed the blank view and lost the user’s framing, confirming the restore as the cause. and now accepts the ecosystem’s vocabularies. Previously any non-empty string was accepted, stored, and then ignored by the frontend if it was not one of the eight curated tags — so set_color_scheme("chain-id") (the Mol* name) appeared to work while actually doing nothing, leaving Mol*’s default coloring on screen. Scheme names are now resolved to their canonical tag, accepting the canonical tags (chain_default…), the underlying Mol* theme names (chain-id, element-symbol… derived from the registry’s own molstar_theme field, so they cannot drift), and MolSysMT attribute names (chain_id, group_name, entity_id, element). Unknown names now raise ArgumentError listing the valid options. The color_scheme representation parameter resolves the same synonyms but still passes unknown values through, because it is shared with non-structural visuals that use their own schemes (e.g. pharmacophore_default). The scheme registry moved to molsysviewer/_private/color_schemes.py (re-exported from styles) so argument digesters can use it without a circular import.

  • 2026-07-17: ArgDigest digester added for the scheme argument of Whole.set_color_scheme() / Region.set_color_scheme(), which was emitting DigestNotDigestedWarning on every call.

  • 2026-07-17: ArgDigest digesters added for the color-operation arguments value_range and replace. The public scalar-color methods (Region/Whole set_color_by_attribute / set_color_by_values) declare and use both arguments under @digest() but had no digester, so every ordinary call emitted a DigestNotDigestedWarning (leaving the public contract un-validated and adding integration noise downstream). digest_value_range accepts None (range inferred from the data) or a list/tuple/1-D numpy array of exactly two finite reals (vmin, vmax) with vmin <= vmax, normalizing to a [float, float] pair (equal bounds are valid; the color mapper handles a zero span); digest_replace accepts only bool, with no integer/string coercion. Both reject invalid input with ArgumentError at the public boundary. New tests/test_color_digesters.py covers the unit contract, and test_argdigest_public_api.py asserts no missing-digester warning across all four color surfaces (mutation-verified).

  • 2026-07-29: Whole.set_color(color) and Region.set_color(color) add the direct uniform-color API requested during dogfooding. Both write through the existing layered per-atom color contract: whole color replaces only the base layer, region color replaces only that region’s atoms, and a state-None region remains colorable through the whole representation. Named, hexadecimal, packed-integer, and RGB colors use the shared color normalization boundary.

  • 2026-07-30: Runtime envelope seam (R1). A shared manifest molsysviewer/runtime_actions.json classifies every browser-originated action (command/event/request/ack/error), with Python-only outbound_requests and raw/data_plane groups excluded from enveloping; Python (runtime_contract.py, viewer/runtime_router.py) and TypeScript (messages/runtime-actions.ts, messages/widget-envelope.ts) load the same file, so both sides classify identically by construction. Python is the sole authority: inbound envelopes are validated for identity, direction and action↔payload coherence, and command messages are deduplicated so one accepted command yields one public-API mutation and one history checkpoint (a duplicate returns an observable command_duplicate_ack and is not re-applied). Enveloping lives in MolSysViewerWidget.send — the connector owns its wire format — so Qt stays raw and initial_messages / _message_history keep domain messages.

  • 2026-07-30: Canonical popup scene snapshot (R2). MolSysView.build_popup_scene_snapshot(mode, endpoint) rebuilds the current scene from live registries instead of replaying a journal: pure with respect to history and transport, _message_history and _build_export_messages() off limits, defensive copies, strict canvas/panel mode, dynamic regions materialized at the current frame, camera excluded as host-local ephemeral state. Inflating the journal with 10,000 unrelated ops leaves the snapshot byte-for-byte identical. Wired as a request/response across the seam: the popup emits ready, the host asks Python for request_popup_scene_snapshot, Python answers with a correlated projection, and the host consumes it at the seam and bootstraps. PopupReplayLog survives only as a timeout fallback.

  • 2026-07-30: Array-native transport hardening (D3/D4). Acknowledgement deadline (30 s, restarted on every accepted ack) evaluated on main-thread entry points only — no timer thread, because widget.send is unsafe off the kernel thread for AnyWidget; on expiry the retained arrays are released explicitly, the receiver is told to cancel, and the recorded JSON load is delivered with a RuntimeWarning. Coordinates now travel structure-planar-c ([structures, 3, atoms]) so Mol* frames are zero-copy subarray views, removing a per-frame de-interleaving pass (930k scalar assignments and 15k allocations on 5,000×62; 30M and a full second copy on 100×100,000) at no cost in Python. A canvas popup receives its own typed molecular generation, streamed to its endpoint and relayed by the host without retaining anything, which lifted the restriction that disabled the binary path whenever enable_popout was set. PopupHostManager.sendTo delivers to one endpoint, fixing a leak where a canvas bootstrap also reached an open panel popup.

  • 2026-07-30: Pre-1.0 scale guard. MolSysViewer materializes every selected structure by design, so molsysviewer.config.set_structure_scale_budget(bytes) and _private/scale_budget.py turn an unbounded silent failure into a documented ceiling: a load whose coordinates exceed the budget (256 MB by default) warns with the measured size, notes that a canvas popup doubles the renderer-side cost, and suggests a concrete structure_indices=range(0, N, stride) that fits. It warns and never refuses; 0 silences it. Fixed a latent bug surfaced while wiring it: load_from_molsysmt called structures.get_n_structures(), which does not exist — the call always raised into a bare except Exception, so n_structures silently stayed None and was only recovered later by counting the serialized payload.
