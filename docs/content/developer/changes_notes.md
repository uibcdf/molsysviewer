# Changes notes

This page tracks major architectural and documentation milestones.

- 2025-11-18: Initial developer docs structure created.
- 2025-11-21: Shapes and loaders refactor; API simplified.
- 2025-12-07: Popup sync, regions/layers/whole, and trajectory controls stabilized.
- 2026-01-XX: Developer documentation consolidated under `docs/content/developer/`.
- 2026-04-20: Annotations API hardened: `add_annotation(selection=...)` replaces `add_label(group_index=...)` as primary entry point; `set_anchor(tag, selection=...)` replaces `set_group_index`; both deprecated forms kept with `DeprecationWarning`. `selections.add(tag, *, atom_indices)` added as direct-index shortcut. All pre-existing test failures fixed and test suite aligned with current module layout (`viewer/core.py`).
- 2026-04-20: Annotation label visual knobs: `add_annotation(..., label_style={...})` accepts `color`, `size_em`, `background`, `background_opacity`; forwarded via `LabelStyle` TS type to Mol* `addLabel` as `visualParams`. Layer-level visibility wired and fixed for shared `layer_tag` groups (`layerTagIndex` map in `AnnotationHandlers`). Canvas pickability implemented: `tooltip: tag` passed in `visualParams` enables `pickable: true` in Mol*'s `StructureSelectionsLabel3D`; hover/click events on labels are detected via `ev.current.repr.props.tooltip` and emitted as `{ kind: "annotation", tag, text, atom_indices }` instead of the underlying atom loci. `registerInteractionObservers` extended with optional `notifyHover`/`notifyClick` override callbacks.
- 2026-04-20: State serialization: `viewer.export_state()` → JSON-serializable dict (annotations, measurements, selections, regions with atom_indices); `viewer.import_state(state, clear_first=True)` replays all on a viewer with compatible structure. numpy int/float types auto-converted. 11 new tests.
- 2026-04-20: Measurement style & pickability: `add_distance/angle/dihedral(..., measurement_style={...})` accepts `color`, `size_em`, `background`, `background_opacity`. Measurements now receive `tooltip: tag` in `visualParams` enabling canvas pickability (same mechanism as annotations); hover/click on measurement visuals emits `{ kind: "measurement", tag, atom_indices, measurement_name }`. `layer_tag` grouping added to `MeasurementHandlers` via `layerTagIndex` map. Python event callbacks added: `viewer.on_hover(fn)`, `viewer.on_click(fn)`, `viewer.on_context(fn)` / `off_*` for reactive (non-polling) interaction handling.
- 2026-04-20: Bloque Q — E2E and unit test coverage for annotations + measurements + pickability: `resolveTooltipPayload` extracted as testable pure function (5 new unit tests); `annotations-interaction.e2e.ts` E2E (5 scenarios: add_label with style, layer visibility toggle, annotation registry, measurement_style, tooltip resolution). JS unit tests now 90 total; E2E suite adds `test:e2e:annotations` script.
- 2026-04-20: Annotation structure-awareness (Bloque T): annotations follow atoms across structures automatically via Mol*'s `MultiStructureSelectionFromBundle` with `isTransitive: true`. No additional code required; the `StructureElement.Loci` → serialized bundle approach re-evaluates topologically when the model index changes.
- 2026-04-20: Structure-aware shapes: `add_sphere(structure_centers=...)`, `add_triangle_faces(structure_vertices=...)`, `add_links(structure_coordinate_pairs=...)`, `add_channel_tube(structure_centers=...)` accept per-structure coordinate arrays in Angstroms; `add_hbonds(structures=[None, [[d,a],...], ...])` accepts per-structure atom-index pairs — JS looks up current-structure coordinates automatically, storing only topology. `ShapeHandlers` subscribes to structure changes via `onTrajectoryState` and clears+rebuilds affected shapes on each structure change. A `None` entry in a structure slot hides the shape on that structure. Wire key renamed `structures_coords` / `structures_atom_pairs`. `@signal(tags=["trajectory"])` renamed to `["structures"]` throughout public API.
- 2026-04-21: Test coverage expansion (sections 1, 2, 3, 8): `shape-handler.test.ts` +11 JS unit tests (structures_coords storage for all 5 trajectory-shape families, frame subscription lifecycle, concurrent guard); `tests/test_protocol_contracts.py` +12 Python tests (reset_viewer/clear_all, clear_decorations/clear_scene flags, annotation/measurement layer retag history rewrite, set_global_representation replay after rebuild); `tests/test_rebuild_visibility.py` +5 Python tests (hidden-region stickiness post-rebuild + global show/hide cycle, annotation retag survival, selection index remapping, style replay across two rebuilds). JS suite now 101 tests, all passing.
- 2026-04-21: Context menu region actions (section 6.6): "Create Region from Selection" now opens an inline tag composer (optional tag, same pattern as Save Selection) instead of auto-creating immediately; region rows in context menu gain eye-icon toggle (hide/show) and trash-icon delete buttons; new `ContextMenuAction` types `toggle_region_visibility` and `delete_region` wired through JS controller to Python handlers (`region.hide()` / `region.show()` / `region.delete()`); `new_region_from_active_selection` now receives the user-supplied tag from the composer. 90/90 JS unit tests passing.
- 2026-04-21: Canvas UX modes implemented: `controls_mode="minimal"` adds a 3-icon SVG cluster (panel/fullscreen/popup) + `?` help button in `controls.ts`; `HelpOverlay` shows a two-column cheat-sheet (Mouse | Keyboard) on `H` key or button click; `N`/`W` keyboard shortcuts toggle Navigate/Workbench panels; empty-canvas context menu gains Reset View, Toggle Background, Toggle Spin, Toggle Swing. `panel_mode_style="floating"` adds a centered overlay shell (`FloatingPanelShell` in `ui/floating-panel-shell.ts`): `~72% × 68%` of canvas, rounded card, backdrop-click-to-close, zero viewport shift; `GroupPanel` and `WorkbenchPanel` accept `{ floating: true }` to use the new shell; `MolSysViewerController.create()` accepts `{ panelModeStyle }` option threaded from `model.get("panel_mode_style")`; Python trait `panel_mode_style` added to `widget.py`, `config/__init__.py`, `viewer/core.py`. Both `"classic"`/`"drawer"` remain defaults; experimental modes activated by explicit constructor argument. 90/90 JS unit tests passing.
- 2026-04-20: Devguide consolidated: `roadmap.md` updated to reflect all completed annotation/measurement/shape objectives; new section 5.5 records canvas minimal UX gap and transition strategy. `devguide/annotations.md` updated — Objectives A/B/C all marked ✓ with implementation details; pending section lists only genuinely deferred items. `devguide/canvas_panel_transition.md` created: documents coexistence strategy for drawer vs. floating panel and classic vs. minimal controls surface, configuration seam (`controls_mode`, `panel_mode_style`), prerequisites before switching defaults, and closing criteria at `0.16.x → 0.17.x` boundary. `docs/content/developer/public_api.md` updated: added full `view.measurements` management API, `measurement_style` parameter, Python event callbacks (`on_hover/click/context`), state serialization (`export_state`/`import_state`), structure controls (`set_structure`, `play`, `pause`, `set_play_speed`), and structure-aware shape parameters.
- 2026-04-26: Context menu richer flows (Option A): label style from context menu — color picker + size slider injected into `add_label_from_active_selection`; multi-group labels from context menu no longer restricted to single-group selections; region rename via inline pencil → tag composer → `RenameRegionMessage` TS → `Region.rename(new_tag)` Python, which updates JS `regionIndex` and Python `_regions` dict simultaneously; `ContextActionDetails` extended with `label_style` and `new_tag` fields; Back-nav fixed on all multi-step composer flows. JS unit tests extended to cover the new context action paths.
- 2026-04-26: Export replay correctness for region rename (Option B): `HistoryMixin._record_shape_message` extended to handle `rename_region` — rewrites all prior `create_region` / `set_region_representation` / `show_region` / `hide_region` / `delete_region` entries in `_message_history` to use the new tag, then drops the `rename_region` message itself, so `_build_export_messages()` / HTML export emit the final tag from the start with no rename step. Four new tests in `tests/test_reproducible_interaction.py`: context rename updates export, label_style stored in annotation records, multi-group label from context action, and a full scientific workflow (create region → rename → multi-group styled label → distance measurement → export verification).
- 2026-04-26: Test suite alignment: fixed 13 pre-existing failures across shapes, addons, and loaders. Shape DummyView stubs were missing `_next_shape_tag()`; expected coordinate/radius values updated from nm to Å (×10) after wire-format change. `add_spheres` plural API replaced by `add_sphere` batch (2D center array) in `test_shapes.py` and `test_argdigest_public_api.py`. `importlib.machinery.ModuleSpec` import corrected in `test_addons.py`. `get_n_atoms()` added to `DummyMolSys` stubs in `test_load_from_molsysmt.py`. `set_addon_runtime_summary` filtered from assertions in `test_build_html_state.py`.

- 2026-04-28: Focus Styles API: `view.styles.focus(style_or_tag, *, selection, representation, **params)` creates named additive overlays over the current scene baseline without resetting it. `BUILTIN_FOCUS_STYLES` dict exposes four pre-built focus styles (`"hydrophobicity"`, `"secondary-structure"`, `"chain-id"`, `"element-cpk"`). `view.styles.clear_focus(tag=None)` removes one or all active overlays; `view.styles.focus_tags()` lists active overlay tags. `Style(kind="focus", representation=...)` is the corresponding data type. 16 new tests in `tests/test_styles.py`.

- 2026-04-28: Project config convenience bridge: `view.load_project_config(path, apply_default=False)` loads styles (via `view.styles.load_project_config`) and add-on defaults (via `msv.addons.load_project_config`) in a single call. `ADDONS_ENABLED` and `ADDONS_DISABLED` documented in `docs/content/user/introduction/project_configuration.md`. `molsysviewer.config` module now exported at top level (`msv.config`).`Region._scoped_indices_for_element("bond")` implemented via `msm.get(..., bond_index=True)`; 2 new tests.
- 2026-07-12: Scene manager API unified around callable `add/tags/count/records/info/contains/get/delete/clear/set_tag` operations. `view.layers` is now a live `LayersManager` dict subclass and `view.layers.add(...)` replaces `view.new_layer(...)`; annotation and selection `tags` are methods. Scene-object identity is domain-qualified as `(kind, tag)`, so different domains may safely share a tag. Undeclared `GroupLayer` and `add_gaussian_isosurface` aliases were removed.
- 2026-07-14: The ElasNetMT add-on was renamed to **ElastNetMT**. The Python package is now `elastnetmt`, the MolSysViewer bridge module is `molsysviewer_elastnetmt`, and `KNOWN_ADDON_MODULES` discovers the new name only. Environments with the old package installed must reinstall it; the previous module name is no longer discovered.
- 2026-07-15: Breaking scene-manager consistency fix: `info(tag)` now returns a `dict` for one tag across regions, shapes, annotations, measurements, and layers; shapes and measurements previously returned a one-element list. A missing tag raises `ValueError` in all five managers; regions and layers previously leaked `KeyError`. Calling `info()` without a tag continues to return a list.
- 2026-07-15: Layer summaries no longer expose `kind`: a layer can contain objects from several scene domains, so reporting the last attached member's kind was misleading. The internal `Layer.kind` protocol/state field remains unchanged.
- 2026-07-15: Scene-object creator attribution added. Add-ons can wrap public scene construction in `with view.attributed_to("elastnetmt"):`; layers, regions, shapes, annotations, measurements, and sections created inside expose an immutable `owner` property. The optional owner is shown in Studio summaries and survives state-v2 export/import. It is informational only and never restricts rename, movement, visibility, or deletion. Older v2 documents without `owner` restore objects as user-created (`owner=None`).
- 2026-07-15: Studio > Viewport now manages persisted clipping sections end to end: create at the active-selection center, show/hide, edit point and normal, invert, and delete. `Section.visible`, `show()`, `hide()`, and atomic `set_geometry()` keep state-v2 replay and scene undo coherent; section summaries are runtime-only and resent after frontend readiness. Section centers are calculated through `molsysmt.structure.get_center`, and point-edit payloads carry explicit units for Python conversion.
