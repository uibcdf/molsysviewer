- 2026-07-17: MolSysViewer no longer vendors its own molecular demo systems. `demo[...]` and the public `molsysviewer.systems` catalog now resolve every system through MolSysMT's registry (`molsysmt.systems`), the ecosystem's single source of truth, so the demos never drift out of sync with MolSysMT. - 2026-07-17: Per-atom colors (`set_color_by_attribute` / `set_color_by_values`) now actually render. The `msv-per-atom` color theme had two defects that made scalar coloring silently invisible: (1) it only handled `StructureElement.Location`, so every `Bond.Location` fell back to the base theme — which meant per-atom colors never showed on bond-drawing representations (ball-and-stick, licorice, line), while cartoon worked; and (2) it resolved the atom via `OrderedSet.getAt(unit.elements, location.element)`, treating a model-level `ElementIndex` as a position into the unit's element array, so lookups only succeeded on the first unit and silently missed on every other chain. Both now follow the same convention as the sibling `physicochemical` theme. Three new JS tests cover the theme's `color()` function (previously only the color map was tested, which is why the defects went unnoticed); each half of the fix is mutation-verified.
- 2026-07-17: Right-dragging the structure no longer leaves the canvas context menu open. The browser fires `contextmenu` on button press, so the menu appears before a click can be told apart from a drag — and Mol* uses the right button to pan, leaving the menu open for the whole gesture. The menu is now dismissed as soon as the pointer travels more than 5 px (measured radially) from where it opened, so a plain right-click, including a shaky one, still works.
- 2026-07-17: The structural color selector offers `group_name` ("Group Name") instead of `residue_name`. The panel builds its options from the backend's scheme list, so this follows from the canonical tag rename; the composer's fallback list was aligned too. Note that `molsysviewer/loaders/load_molsysmt.py` deliberately keeps translating `group_*` to `residue_*` in the wire payload, because those fields are written into mmCIF `atom_site` columns (`label_comp_id`, `label_seq_id`) where *comp*/residue is the standard name — that boundary is intentional and stays.
- 2026-07-17: A pure color change no longer rebuilds the global representation. `set_color_scheme()` emits the same `set_whole_representation` op as `set_representation()`, so the frontend used to destroy and recreate the representations for a mere recolor. That triggered Mol*-internal camera adjustments and made atoms the representation cannot draw (waters under a cartoon) blink out on an operation that should only change color. When the representation, preset and non-color params are unchanged, the color theme is now updated in place; an active per-atom color overlay is preserved and only its base theme is replaced.
- 2026-07-17: The camera is only preserved across a representation rebuild when a deliberate viewpoint exists. Restoring it unconditionally was wrong: when operations arrive before Mol* has framed a freshly loaded structure — configuring a view before displaying it, or simply running notebook cells faster than the render — the snapshot predates that framing and writing it back overwrote it, leaving the structure rendered but out of sight until the user pressed "Reset view". A viewpoint counts as deliberate when the user has orbited/zoomed/panned, when a camera snapshot was applied explicitly, or when the view was focused on a selection; otherwise Mol* is left free to frame the structure. Diagnosed by disabling the restore entirely, which fixed the blank view and lost the user's framing, confirming the restore as the cause. and now accepts the ecosystem's vocabularies. Previously any non-empty string was accepted, stored, and then ignored by the frontend if it was not one of the eight curated tags — so `set_color_scheme("chain-id")` (the Mol* name) appeared to work while actually doing nothing, leaving Mol*'s default coloring on screen. Scheme names are now resolved to their canonical tag, accepting the canonical tags (`chain_default`…), the underlying Mol* theme names (`chain-id`, `element-symbol`… derived from the registry's own `molstar_theme` field, so they cannot drift), and MolSysMT attribute names (`chain_id`, `group_name`, `entity_id`, `element`). Unknown names now raise `ArgumentError` listing the valid options. The `color_scheme` representation parameter resolves the same synonyms but still passes unknown values through, because it is shared with non-structural visuals that use their own schemes (e.g. `pharmacophore_default`). The scheme registry moved to `molsysviewer/_private/color_schemes.py` (re-exported from `styles`) so argument digesters can use it without a circular import.
- 2026-07-17: ArgDigest digester added for the `scheme` argument of `Whole.set_color_scheme()` / `Region.set_color_scheme()`, which was emitting `DigestNotDigestedWarning` on every call.
- 2026-07-17: ArgDigest digesters added for the color-operation arguments `value_range` and `replace`. The public scalar-color methods (`Region`/`Whole` `set_color_by_attribute` / `set_color_by_values`) declare and use both arguments under `@digest()` but had no digester, so every ordinary call emitted a `DigestNotDigestedWarning` (leaving the public contract un-validated and adding integration noise downstream). `digest_value_range` accepts `None` (range inferred from the data) or a `list`/`tuple`/1-D `numpy` array of exactly two finite reals `(vmin, vmax)` with `vmin <= vmax`, normalizing to a `[float, float]` pair (equal bounds are valid; the color mapper handles a zero span); `digest_replace` accepts only `bool`, with no integer/string coercion. Both reject invalid input with `ArgumentError` at the public boundary. New `tests/test_color_digesters.py` covers the unit contract, and `test_argdigest_public_api.py` asserts no missing-digester warning across all four color surfaces (mutation-verified).
